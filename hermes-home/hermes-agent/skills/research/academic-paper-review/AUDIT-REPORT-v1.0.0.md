## 维度一：审稿维度覆盖

### 问题 1.1 — 「结构完整性检查」位置错误，形同虚设
**严重程度**: 🔴 Critical

**现状**: 结构完整性检查段落位于文件第 315-329 行（接近文件末尾），在所有审稿人框架定义之后、注意事项之前。它声明"在进入各审稿人视角之前"执行，但实际编排位置暗示它是事后补充的 patch，而非流程核心步骤。

**问题分析**:
- 该段落在文件中的物理位置远离 Phase 0（论文信息提取，第 39 行），没有编号为独立 Phase，容易被 AI 串行执行时跳过
- 标题为"结构完整性检查（所有模式必备）"但没有像 Phase 0/Phase 1/Phase 2 那样有明确的 Phase 编号
- 没有定义输出格式——做完检查后结果写在哪里？没有模板

**改进建议**:
1. 将结构完整性检查正式编为 **Phase 0.5**，位于 Phase 0 和 Phase 1 之间
2. 为结构检查定义独立输出模板，包含各章节字数统计表、比例评估、红色标记项
3. 明确要求各审稿人在自己的报告中引用结构检查结果

### 问题 1.2 — 章节比例审查标准过于粗糙
**严重程度**: 🟠 Major

**现状**: 仅有一条量化规则——"Discussion 字数少于 Results 的 50% 标记为 Major Issue"。

**缺失项**:
- Introduction 占全文比例是否合理（通常 10-15%）
- Method 部分比例是否合理（实验型 20-30%，理论型可更多）
- Results 与 Discussion 比例（健康比例通常 1:0.8~1:1.2）
- 摘要字数是否符合目标期刊要求
- 参考文献数量与论文长度的关系
- 图表数量与论文长度的关系

**改进建议**:
添加完整的章节比例基准表：

```
| 章节 | 健康占比（实验型） | 健康占比（理论型） | 常见问题 |
|------|-------------------|-------------------|---------|
| Abstract | 2-3% | 2-3% | 超过 300 词 |
| Introduction | 10-15% | 15-20% | 文献综述过薄/过厚 |
| Method | 20-30% | 25-35% | 关键参数缺失 |
| Results | 25-35% | 20-30% | 数据堆砌无解释 |
| Discussion | 20-30% | 15-25% | ⚠️ 最易过薄 |
| Conclusion | 3-5% | 3-5% | 简单重复摘要 |
```

### 问题 1.3 — 缺少写作质量审查维度
**严重程度**: 🟡 Moderate

**现状**: 5 个审稿人中没有一个专门负责写作质量——语言清晰度、段落结构、图表质量、引用格式。

**缺失项**:
- 段落是否有明确的主题句
- 图表是否自包含（不看正文也能理解图表含义）
- 学术语言规范性
- 过渡句/段是否充分
- 术语一致性（全文是否统一使用同一术语）

**改进建议**: 在 EIC 的"总体质量信号"中拆出一个子维度"写作与呈现质量"，或将此维度加入跨学科视角（该角色最需要评估"非专家能否读懂"）。

---

### 问题 1.4 — Discussion 深度检查标准不够具体
**严重程度**: 🟠 Major

**现状**: Discussion 检查仅列出"结果解释、与已有工作的定量对比、理论意义、局限性、未来方向"5 个要素，但：
- 没有定义每个要素的最低标准
- 没有区分不同论文类型的 Discussion 结构要求
- 缺少"每个 Result 都必须在 Discussion 中被讨论"的明确规则

**改进建议**:
添加 Discussion 要素检查表：

```
| Discussion 要素 | 最低要求 | 典型缺陷 |
|----------------|---------|---------|
| 结果解释 | 每个 Result 核心数据都有"为什么"的解释 | 只重复数据不解释 |
| 与文献对比 | 至少 3 处定量对比 | "与 XX 一致"但无具体数值 |
| 理论意义 | 明确说明对理论的推进 | 笼统的"有重要意义" |
| 局限性 | 至少 3 条具体、可量化的局限性 | "未考虑XX"式笼统 |
| 未来方向 | 每个局限性对应具体技术路径 | "需要进一步研究" |
```

## 维度二：各审稿人角色的差异化

### 问题 2.1 — 方法论专家与魔鬼代言人的"统计审查"重叠
**严重程度**: 🟡 Moderate

**现状**:
- 方法论专家维度 7: "统计严谨性 — 效应量、置信区间、多重比较校正、样本量论证"
- 魔鬼代言人维度 6: "统计陷阱 — p-hacking、HARKing、发表偏倚、幸存者偏差"

两者都涉及统计方法审查，但角度不同（前者是建设性的"是否正确"，后者是批判性的"是否有操纵嫌疑"）。

**改进建议**: 在方法论专家中明确限定为"统计方法是否正确使用"，在魔鬼代言人中明确限定为"是否存在统计不端行为嫌疑"，并在 Skill 中明确注释两者的边界。

---

### 问题 2.2 — 领域专家与魔鬼代言人的"结果解释"重叠
**严重程度**: 🟡 Moderate

**现状**:
- 领域专家维度 6: "结果解释合理性 — 结论是否超出了数据的支撑范围？"
- 魔鬼代言人维度 2: "替代解释 — 是否存在同样合理的替代解释？"

**改进建议**: 领域专家聚焦"在领域共识框架内，解释是否恰当"；魔鬼代言人聚焦"是否存在完全不同的解释框架"。明确边界。

---

### 问题 2.3 — 跨学科视角与方法论专家的"效度"重叠
**严重程度**: 🟡 Moderate

**现状**:
- 方法论专家维度 5: "效度与信度 — 内部效度、外部效度、构念效度"
- 跨学科视角维度 2: "外部有效性 — 在不同文化/制度/学科背景下是否仍然成立？"

**改进建议**: 方法论专家负责"研究设计内部的效度威胁"；跨学科视角负责"结论的可推广性边界"。明确分工。

---

### 问题 2.4 — 🟠 没有任何审稿人"拥有"论文结构完整性
**严重程度**: 🟠 Major（这是系统性盲区的根本原因）

**现状**: 
- EIC 的"结构一致性"维度（维度 4）覆盖的是"标题→摘要→引言→结论的逻辑断裂"，不是章节深度和比例
- 结构完整性检查段落是独立的"前置检查"，不归属任何审稿人
- 结果：没有人对"Discussion 太薄"负责

**改进建议**:
1. 将结构完整性检查的**执行责任**明确分配给 EIC
2. 在 EIC 评审维度中增加"章节结构完整性"作为正式维度（与现有"结构一致性"并列）
3. 其他审稿人在看到结构检查结果后，应在其负责的维度中引用（如方法论专家在 Discussion 缺少方法局限性讨论时标记）

---

### 问题 2.5 — EIC 角色定义过于宽泛
**严重程度**: 🟡 Moderate

**现状**: EIC 同时负责原创性评估、重要性评估、结构一致性、期刊适配度、总体质量——这 5 个维度跨度极大。在实际执行中，AI 可能会偏重某几个而忽略其他。

**改进建议**: 将 EIC 的维度分为"必检"和"选检"，或拆分为 EIC-宏观（原创性、重要性、期刊适配度）和 EIC-结构（结构完整性、写作质量）两个子角色。

## 维度三：评审标准是否明确可量化

### 问题 3.1 — 🔴 评分体系缺乏锚定点（Anchor Points）
**严重程度**: 🔴 Critical

**现状**: 
- EIC 的"第一印象"有 1-10 分但没有定义 1/3/5/7/10 分别代表什么
- 方法论评分矩阵有 1-5 分但同样没有锚定
- 原创性/重要性/结构一致性只有"高/中/低"三级定性标签
- 领域专家没有任何评分体系
- 跨学科视角没有任何评分体系
- 魔鬼代言人没有任何评分体系

**后果**: 同一篇论文，不同次执行可能给出完全不同的评分，无法保证评审的一致性和可重复性。

**改进建议**: 为所有评分添加锚定点。

示例——方法论 1-5 分锚定表：
```
5 = 卓越：方法无瑕疵，可作为领域标杆。无需任何改进。
4 = 良好：方法基本正确，有微小改进空间。不影响结论可信度。
3 = 及格：方法大体正确，但存在明显可改进之处。结论可信但需说明限制。
2 = 不足：方法存在显著缺陷，可能影响结论。需要大修后重新评估。
1 = 不可接受：方法根本性错误，结论不可信。需要完全重新设计。
```

示例——原创性锚定表：
```
高 = 提出了全新的理论/方法/视角，或首次在全新场景验证已有理论
中 = 在已有框架上做了有意义的扩展或组合
低 = 主要是重复验证、增量式改进、或换个数据集重跑
```

---

### 问题 3.2 — 置信度评分缺乏使用指导
**严重程度**: 🟡 Moderate

**现状**: 置信度只有 1-5 标注（1=完全外行, 5=完全内行），但没有说明：
- 置信度如何影响评审权重？
- 低置信度的评审是否应该降低其建议的影响力？
- 置信度是自我声明还是应该有客观标准？

**改进建议**: 添加置信度与建议权重的关系说明，以及置信度自评标准。

---

### 问题 3.3 — 严重程度分级不一致
**严重程度**: 🟡 Moderate

**现状**:
- 魔鬼代言人使用 Critical / Major / Minor 三级
- 编辑决定信的"必须修改项"也使用 Critical 严重程度
- EIC 使用 Accept / Minor Revision / Major Revision / Reject 四级
- 其他审稿人没有统一的严重程度分级

**改进建议**: 统一全 skill 的严重程度分级体系，定义三级（Critical = 致命缺陷影响结论可信度 / Major = 显著缺陷需要修改但不影响核心结论 / Minor = 小问题不影响结论）。所有审稿人的每个问题都应标注此三级之一。

## 维度四：输出格式是否实用

### 问题 4.1 — 🔴 跨学科视角完全没有输出格式
**严重程度**: 🔴 Critical

**现状**: 跨学科视角（Peer Reviewer 3）的评审维度列完后直接是 `---`，没有像其他 4 个审稿人那样定义输出模板。

**对比**:
- EIC: 有完整输出模板（第 88-118 行）
- 方法论: 有完整输出模板（第 138-163 行）
- 领域专家: 有输出模板（第 181-203 行）
- **跨学科: 无输出模板** ❌
- 魔鬼代言人: 有完整输出模板（第 236-253 行）

**后果**: AI 执行时对跨学科视角的输出完全自由发挥，无法保证格式一致性，也无法在编辑综合阶段有效提取信息。

**改进建议**: 补充跨学科视角的输出模板，至少应包含：
```
## 跨学科评审报告

### 研究者身份
[跨学科专家身份描述，说明其原始领域和与论文领域的关系]

### 总体建议 & 置信度
[Accept/Minor/Major/Reject] | 置信度 [1-5]

### 跨学科可迁移性评分
[1-5] — [具体分析]

### 核心跨学科问题
1. [问题描述 + 跨学科视角 + 修改建议]

### 隐含假设审查
1. [假设描述 + 在哪些学科背景下不成立]

### 亮点（跨学科视角）
1. [对其他领域有启发的内容]
```

## 维度五：系统盲区分析 — 为什么 5 个审稿人全部漏掉 Discussion 薄弱

### 根因分析

这是一个**系统性设计缺陷**，不是单点失败。5 个审稿人全部漏掉的原因可以用"瑞士奶酪模型"解释——多层防线各有漏洞，恰好对齐时事故发生。

#### 防线 1：结构完整性检查段落（设计存在，但执行失败）
- **漏洞**: 该段落位于文件末尾（第 315 行），远离核心流程定义（Phase 0/1/2）
- **漏洞**: 没有定义输出模板，AI 执行后无法确保结果被保留
- **漏洞**: 没有编号为正式 Phase，容易被当作"注意事项"而非执行步骤
- **瑞士奶酪孔**: 该检查可能执行了，但结果没有被传递到各审稿人

#### 防线 2：EIC 的"结构一致性"维度
- **漏洞**: 该维度定义为"标题→摘要→引言→结论是否有逻辑断裂"，聚焦的是叙事逻辑链，不是章节深度/比例
- **漏洞**: Discussion 不在该维度的检查范围内
- **瑞士奶酪孔**: EIC 检查了逻辑断裂，但逻辑断裂 ≠ 结构不完整

#### 防线 3：方法论专家
- **漏洞**: 方法论专家的维度全部聚焦于"方法是否正确"，不涉及"Discussion 是否充分讨论了方法的结果和局限"
- **瑞士奶酪孔**: 即使方法有局限，方法论专家也只检查"方法本身"而非"方法局限是否在 Discussion 中被充分讨论"

#### 防线 4：领域专家
- **漏洞**: 领域专家维度 6 是"结果解释合理性"，但这是检查解释是否正确，不是检查解释是否充分
- **漏洞**: 200 字的 Discussion 可能有正确的解释但深度严重不足
- **瑞士奶酪孔**: 领域专家检查了"说的对不对"但没有检查"说够了没有"

#### 防线 5：跨学科视角 + 魔鬼代言人
- **漏洞**: 这两个角色完全聚焦于内容层面（可迁移性、替代解释、逻辑漏洞），根本不涉及写作结构
- **瑞士奶酪孔**: 这两个角色天然不会关注结构性问题

#### 结论：系统性盲区的形成机制
```
结构检查段落 → 存在但位置错误，执行无保障 ❌
EIC → 检查逻辑一致性，不检查章节深度 ❌
方法论 → 检查方法正确性，不检查讨论充分性 ❌
领域专家 → 检查解释正确性，不检查解释充分性 ❌
跨学科 → 完全不涉及结构 ❌
魔鬼代言人 → 完全不涉及结构 ❌
───────────────────────────────
结果：Discussion 过薄 → 无人报告 ⚠️
```

### 改进方案（必须同时执行，缺一不可）

1. **将结构完整性检查升级为 Phase 0.5**，有独立输出模板
2. **在 EIC 维度中新增"章节结构与深度"维度**，明确 EIC 是结构完整性的第一责任人
3. **在所有审稿人的注意事项中增加一行**: "参考 Phase 0.5 结构检查结果，如果 Discussion 被标记为不完整，你应在你的维度中评估这是否影响了你负责的方面"
4. **在方法论专家中增加维度**: "Discussion 是否充分讨论了方法局限性和结果的不确定性"
5. **在领域专家中增加维度**: "Discussion 与领域内同类研究的对比深度是否足够"
