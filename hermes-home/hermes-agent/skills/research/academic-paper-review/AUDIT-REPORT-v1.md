# Academic Paper Review Skill — 质量审查报告

**审查日期**: 2026-06-02
**审查版本**: SKILL.md v1.0.0
**审查人**: Hermes Subagent (质量审查专用)
**严重程度定义**: 🔴 Critical (导致系统性失效) | 🟠 Major (显著降低评审质量) | 🟡 Minor (可改进但不影响核心功能)

## 维度一：审稿维度覆盖

### 问题 1.1 🔴 Critical — 结构完整性检查"悬空"，未集成到任何审稿人的评审流程中

**现状**: SKILL.md 第315-329行有"结构完整性检查"章节，标注"所有模式必备"，但：
- 它位于文件末尾（第315行），在所有5个审稿人的框架定义之后
- 没有任何审稿人的"评审维度"列表引用这个检查清单
- 没有任何审稿人的"输出格式"模板包含结构完整性的输出字段
- 虽然注明"在进入各审稿人视角之前，先做一轮结构完整性扫描"，但没有定义输出格式和位置

**影响**: 这正是模拟审稿中5个审稿人全部忽略Discussion薄弱的根因——结构检查是"建议"而非"强制嵌入"。

**改进建议**:
1. 将结构完整性检查从文件末尾移到 Phase 0.5（在Phase 0信息提取后、Phase 1独立评审前）
2. 为结构检查定义明确的输出模板
3. 在每个审稿人的框架中增加一行："**前置约束**：必须在 Phase 0.5 结构检查报告的基础上进行评审，对已标记的结构问题不得遗漏"
4. 在编辑综合信中增加"结构完整性评估"专节

### 问题 1.2 🟠 Major — 章节比例审查标准不完整

**现状**: 仅有一条量化规则（"Discussion字数少于Results的50%标记为Major Issue"）。缺失：
- Introduction 与 Method 的合理比例标准
- Abstract 字数合规检查
- 参考文献密度（引用数/论文字数）
- 图表数量与正文的合理比例
- Conclusion 长度与全文比例

**改进建议**: 增加论文类型适配的章节比例标准表：

| 论文类型 | Intro占比 | Method占比 | Results占比 | Discussion占比 | Conclusion |
|---------|----------|-----------|------------|---------------|------------|
| 实验型 | 15-20% | 20-25% | 25-30% | 25-35% | 5-10% |
| 理论型 | 15-20% | 30-40%(推导) | 20-25%(定理) | 20-25% | 5-10% |
| 综述型 | 10-15% | N/A | 60-70%(分主题) | 10-15% | 5-10% |

### 问题 1.3 🟡 Minor — Discussion深度审查维度可以更具体

**现状**: 必检项提到"结果解释、与已有工作的定量对比、理论意义、局限性、未来方向"，但缺少：
- 每个结果是否都有对应的Discussion段落
- Discussion是否有独立的小节结构
- 是否存在Results的简单重复（而非解释）

**改进建议**: 在必检项中增加"Results-Discussion映射检查"——每个Key Result在Discussion中应有对应的分析段落。

## 维度二：各审稿人角色差异化

### 问题 2.1 🟠 Major — EIC和领域专家存在显著职责重叠

**重叠分析**:
| 评审维度 | EIC | 领域专家 |
|---------|-----|---------|
| 原创性/贡献评估 | ✅ 原创性评估 + 重要性评估 | ✅ 领域贡献评估 |
| 文献/前沿 | （隐含在重要性中） | ✅ 文献综述质量 + 领域前沿对接 |
| 术语/准确性 | — | ✅ 术语准确性 |

EIC 的"原创性评估"和领域专家的"领域贡献评估"高度重叠——两者都在问"这篇论文对领域有什么新东西"。实际执行时，两者很可能产出雷同的评价。

**改进建议**: 
- EIC 专注于"宏观定位"：期刊匹配、读者群、投稿策略、论文的整体storytelling
- 领域专家专注于"专业深度"：文献精确性、方法领域惯例、术语精准度
- 将 EIC 的"原创性"改为"创新定位"（这篇论文在创新图谱中的位置），将"重要性"改为"影响力预判"
- 领域专家的"领域贡献"改为"知识增量评估"（具体对哪个子领域的哪类问题有增量）

### 问题 2.2 🟠 Major — 跨学科视角审稿人完全缺少输出格式定义

**现状**: 跨学科视角（Peer Reviewer 3）的定义在第207-218行，列出了6个评审维度，但：
- **没有定义任何输出格式模板**（其他4个审稿人都有）
- 第219行直接跳到了"---"和魔鬼代言人部分
- 这意味着实际执行时，AI 可能随意输出或干脆跳过这个角色

**改进建议**: 为跨学科视角补充与其它审稿人对等的输出格式模板：
```
## 跨学科评审报告

### 研究者身份
[相邻学科专家身份描述，说明与论文领域的距离]

### 总体建议 & 置信度
[Accept/Minor/Major/Reject] | 置信度 [1-5]

### 跨学科可迁移性评估
[高/中/低] — [哪些领域可迁移 + 转移条件]

### 隐含假设审查
1. [假设描述 + 在跨学科场景下的失效风险 + 建议补充的限定条件]

### 沟通清晰度评估
[非本领域专家能否理解核心贡献？哪些术语/概念需要更多解释？]

### 跨学科启发
[方法/发现对其他领域的启发点]

### 关键问题
1. [问题描述 + 严重程度 + 修改建议]
```

### 问题 2.3 🟡 Minor — 方法论专家与魔鬼代言人在统计审查上有重叠

**重叠点**: 
- 方法论专家维度7："统计严谨性"（效应量、置信区间、多重比较校正）
- 魔鬼代言人维度6："统计陷阱"（p-hacking、HARKing、发表偏倚）

**改进建议**: 
- 方法论专家：聚焦"统计方法是否正确"（正面审查）
- 魔鬼代言人：聚焦"统计结果是否被误用/过度解读"（反面挑战）
- 在各自维度描述中明确区分

### 问题 2.4 🔴 Critical — 没有任何审稿人"拥有"写作质量/结构完整性的审查职责

**现状**: 5个审稿人的视角全部偏向技术内容审查：
- EIC：全局/创新性/期刊匹配
- 方法论：实验设计/统计
- 领域专家：文献/术语/领域惯例
- 跨学科：可迁移性/外部有效性
- 魔鬼代言人：逻辑漏洞/替代解释

**没有任何角色专注于**：
- 写作清晰度与流畅性
- 章节结构完整性和比例
- Discussion 深度和质量
- 图表标注和引用的完整性
- 段落级别的论证结构

虽然"结构完整性检查"章节存在，但它是 Phase 0.5 的前置扫描，不属于任何审稿人。而审稿人在独立评审时，如果自己的维度列表里没有"检查Discussion深度"这一项，就会自然忽略它。

**这正是系统性盲区的根本原因。**

**改进建议（两种方案）**:

**方案A（推荐）— 将结构审查作为EIC的必要维度**：
在EIC的评审维度中增加第7项：

```
7. **论文结构与写作质量**
   - 各章节（尤其Discussion）是否完整、比例适当？
   - Discussion是否深入解释了每个关键结果？
   - 图表是否有充分的文字讨论？
   - 段落间是否有逻辑过渡？
   - 写作是否清晰、简洁、专业？
```

**方案B — 新增第6个角色"写作编辑"**：
但这会增加full模式的复杂度，不推荐。

## 维度三：评审标准是否明确可量化

### 问题 3.1 🔴 Critical — 所有评分标准均无 anchor points

**现状对比**:

| 审稿人 | 评分方式 | Anchor Points |
|--------|---------|---------------|
| EIC 第一印象 | 1-10 | ❌ 无（1代表什么？10代表什么？） |
| EIC 原创性 | 高/中/低 | ❌ 无（什么区分"高"和"中"？） |
| EIC 重要性 | 高/中/低 | ❌ 无 |
| EIC 结构一致性 | 强/中/弱 | ❌ 无 |
| 方法论矩阵 | 1-5 × 6维度 | ❌ 无（1分和5分各代表什么？） |
| 方法论 置信度 | 1-5 | ✅ 有定义（但定义过于简单） |
| 领域专家 | 无量化评分 | ❌ 完全定性 |
| 跨学科视角 | 无量化评分 | ❌ 完全定性 |
| 魔鬼代言人 | 无量化评分 | ❌ 仅有严重程度分类 |

**影响**: 无 anchor points 意味着评分完全依赖 AI 的主观判断，不可复现、不可对比。

**改进建议**: 为每个评分维度定义明确的 anchor points。示例：

**EIC 第一印象评分 (1-10) Anchor Points**:
| 分数 | 含义 | 典型表现 |
|------|------|---------|
| 9-10 | 立即接受 | 选题前沿、方法创新、写作优秀，可直接发表或仅需微调 |
| 7-8 | 小修接受 | 整体优秀，但有小问题需要澄清或补充 |
| 5-6 | 大修 | 核心有价值但执行有缺陷，需要大量修改后重审 |
| 3-4 | 大修或拒稿 | 重大方法论或逻辑问题，修改难度大 |
| 1-2 | 拒稿 | 根本性缺陷（数据造假嫌疑、完全无法回答研究问题等） |

**方法论评分矩阵 (1-5) Anchor Points**:
| 分数 | 含义 |
|------|------|
| 5 | 完全达标，无需改进 |
| 4 | 基本达标，有小瑕疵但不影响结论 |
| 3 | 部分达标，有明显缺陷需要补充 |
| 2 | 不达标，缺陷可能影响结论可靠性 |
| 1 | 严重缺陷，结论不可信 |

**原创性 (高/中/低) Anchor Points**:
| 等级 | 标准 |
|------|------|
| 高 | 提出全新的理论/方法/视角，或跨领域方法迁移首次成功应用 |
| 中 | 对已有方法/理论有显著改进，或在新场景下验证了已有方法 |
| 低 | 增量式改进，或仅在不同数据集上重复验证了已知结论 |

### 问题 3.2 🟠 Major — 领域专家和跨学科视角完全没有量化评分

**现状**: 领域专家输出中只有"[充分/部分/不足]"和"[高/中/低]"，跨学科视角连这些都没有。

**改进建议**: 
- 领域专家：增加类似方法论专家的评分矩阵（文献覆盖度、术语准确性、前沿对接度、理论框架适当性、结果解释合理性 — 各1-5分）
- 跨学科视角：增加可迁移性评分（1-5）和沟通清晰度评分（1-5）

## 维度四：输出格式是否实用

### 问题 4.1 🟠 Major — 审稿意见缺少"位置定位"字段

**现状**: 所有审稿人的"关键问题"格式都是"问题描述 + 修改建议"，但没有指定问题在论文中的具体位置。

**影响**: 用户收到评审报告后，需要自己去找问题对应的论文位置，降低修订效率。

**改进建议**: 所有关键问题的格式改为：
```
1. **[位置: 第X节, 第Y段]** — [问题描述]
   - 严重程度: [Critical/Major/Minor]
   - 当前文本: [引用原文关键句]
   - 修改建议: [具体如何改]
   - 修改后验收标准: [如何确认问题已解决]
```

### 问题 4.2 🟠 Major — 跨学科视角完全缺少输出格式（同问题2.2）

此处不再重复。

### 问题 4.3 🟡 Minor — Phase 2 编辑决定信中"必修项详情"模板不够实用

**现状**: 模板有"验收标准"字段（第298行），这是好的。但缺少：
- 修订的优先级排序（应按Critical→Major→Minor排序）
- 预估修订工作量（虽然表格中有"预估工作量"列，但详情中没有展开）
- 修订的依赖关系（某些修订必须先完成其他修订才能进行）

**改进建议**: 在必修项详情中增加：
```
- **优先级**: [P0=立即处理 / P1=核心修订 / P2=重要改进]
- **依赖项**: [必须先完成的修订项编号]
- **预估工作量**: [X小时/天]
```

### 问题 4.4 🟡 Minor — quick/methodology 模式的输出格式未单独定义

**现状**: 只定义了 full 模式的编辑决定信格式。quick 模式（EIC单人）和 methodology 模式（EIC+方法论）的最终综合输出没有定义。

**改进建议**: 为 quick 和 methodology 模式各定义一个轻量级综合输出格式。

## 维度五：系统盲区分析 — 为什么5个审稿人全部忽略了Discussion薄弱

### 根因分析

**核心问题：结构审查与技术审查的架构性断裂**

SKILL.md 中存在两条并行的审查线路，但它们在执行时是完全解耦的：

```
线路A（Phase 0.5）: 结构完整性检查 → 输出一份报告 → ???
线路B（Phase 1）:  5个审稿人按各自的维度列表独立审查 → 各自输出报告 → Phase 2 综合
```

**断裂点**：
1. **结构检查的输出没有"注入"到任何审稿人的评审框架中**。每个审稿人只看到自己的维度列表，看不到 Phase 0.5 的结论。
2. **审稿人的维度列表中没有"检查论文结构"这一项**。5个角色全部是技术内容导向。
3. **虽然注意事项第8条说"结构审查优先"**，但这是一条一般性建议，不是嵌入在审稿人框架中的硬性检查项。
4. **跨学科视角缺少输出格式**（问题2.2），AI 可能跳过或简化这个角色，进一步减少了发现结构性问题的可能性。

### 模拟推演：AI 在执行 full 模式时的实际行为

1. Phase 0: 提取论文信息 ✅
2. Phase 0.5: 做结构完整性检查 → 生成一份报告 → **这份报告被搁置，因为没有流程节点引用它** ❌
3. Phase 1: EIC 按6个维度审查 → 不包含"Discussion深度" → 跳过 ❌
4. Phase 1: 方法论专家按8个维度审查 → 不包含"结构完整性" → 跳过 ❌
5. Phase 1: 领域专家按7个维度审查 → 不包含"结构完整性" → 跳过 ❌
6. Phase 1: 跨学科视角 → 连输出格式都没有 → 可能被跳过或极度简化 ❌
7. Phase 1: 魔鬼代言人 → 关注逻辑漏洞和替代解释 → 不检查"Discussion是否完整" ❌
8. Phase 2: 综合时 → 没有任何审稿人报告了结构问题 → 编辑信中也没有 ❌

**结论**：Phase 0.5 的结构检查形同虚设。它被设计为一个"独立的前置步骤"，但实际上没有任何机制确保其结果被传递和使用。

### 修复方案

**必要修改（缺一不可）**：

1. **将 Phase 0.5 结构检查的输出格式化并强制注入 Phase 1**
2. **将"论文结构与写作质量"作为 EIC 的第7个评审维度**（问题2.4的方案A）
3. **在编辑综合信模板中增加"结构完整性评估"专节**
4. **为结构检查的每个必检项定义量化阈值**（如 Discussion 字数占比）
