## 维度一：审稿维度覆盖

### 问题 1.1：结构完整性检查位置错误 [严重程度：🔴 Critical]

**现状**：「结构完整性检查」section 放在第315-329行（文件末尾附近），位于所有审稿人框架之后、注意事项之前。

**问题**：
- Skill 文件顶部 Phase 0（论文信息提取）之后直接进入 Phase 1（独立评审），结构完整性检查作为一个孤立的 section 存在，不在任何 Phase 内。
- 流程指令说「在进入各审稿人视角之前，先做一轮结构完整性扫描」——但这句话埋在文件底部，LLM 执行时很可能先处理 Phase 0 → Phase 1，跳过这个孤立的 section。
- 结构完整性检查的结果没有输出模板，没有规定应该以什么格式呈现、放在评审报告的哪个位置。

**改进建议**：
1. 将结构完整性检查明确纳入 Phase 0.5（在 Phase 0 和 Phase 1 之间），作为必经步骤。
2. 为结构完整性检查定义独立的输出模板。
3. 在每个审稿人的评审框架中明确引用结构完整性检查的结果（如：「以下问题来自结构完整性扫描，请在你的评审中回应」）。

### 问题 1.2：章节比例标准不完整 [严重程度：🟡 Major]

**现状**：只规定了「Discussion 字数 < Results 的 50%」这一个比例标准。

**缺失**：
- Introduction 篇幅是否合理（通常占全文 10-15%）
- Method 过长或过短的判断标准
- Abstract 长度是否匹配目标期刊
- References 密度是否正常（不同领域差异大，但应有最低标准）
- 结论部分与 Discussion 的比例

**改进建议**：
- 增加「典型学术论文各章节比例参考表」（可标注为粗略参考，不同领域可调）
- 增加至少 3-4 个比例阈值，如：
  - Abstract: 通常 150-300 词
  - Introduction: 通常占全文 10-20%
  - Method: 实验/理论型通常占 15-30%
  - Discussion: 至少与 Results 等长，理想情况下 1.2-1.5x Results
  - Conclusion: Discussion 的 15-25%

### 问题 1.3：缺乏写作质量审查维度 [严重程度：🟡 Major]

**现状**：5个审稿人均未系统覆盖写作质量（语言流畅性、段落结构、过渡、学术写作规范）。

**缺失**：
- 段落是否有明确的主题句
- 段落间过渡是否自然
- 是否存在冗余表述
- 图表标注和引用是否一致
- 参考文献格式是否统一

**改进建议**：
- 在 EIC 或新增「写作质量」审查维度中增加这些检查项
- 或者在结构完整性检查中增加写作质量子项

## 维度二：各审稿人角色差异化

### 问题 2.1：角色间存在实质性重叠 [严重程度：🟡 Major]

**具体重叠点**：

| 重叠维度 | 涉及审稿人 | 具体重叠 |
|---------|-----------|---------|
| 统计审查 | 方法论专家（#7 统计严谨性）+ 魔鬼代言人（#6 统计陷阱） | 两者都审查统计方法，但方法论偏建设性、魔鬼代言人偏攻击性。实际执行时 LLM 很可能产生冗余评语 |
| 效度审查 | 方法论专家（#5 效度与信度）+ 跨学科视角（#2 外部有效性） | 外部有效性本质上是效度的一个子类型 |
| 结果解释 | 领域专家（#6 结果解释合理性）+ 魔鬼代言人（#2 替代解释） | 领域专家检查「是否过度解释」，魔鬼代言人检查「是否有替代解释」，核心逻辑重叠 |
| 创新性评估 | EIC（#2 原创性评估）+ 跨学科视角（#5 方法创新性） | 都在评估「新」在哪里 |

**改进建议**：
- 为每个重叠点明确划定边界，例如：
  - 方法论专家的统计审查关注「方法是否正确」，魔鬼代言人关注「是否存在统计不端行为」
  - 效度：方法论专家关注内部效度和构念效度，跨学科视角仅关注外部效度
- 在各审稿人框架中加入「本审查员 **不负责** 的维度」边界声明

### 问题 2.2：无人专职负责论文结构与写作 [严重程度：🔴 Critical]

**现状**：
- EIC 的「结构一致性」仅检查 title→abstract→intro→conclusion 的逻辑链，不涉及 Discussion 深度、章节比例等。
- 结构完整性检查 section 存在，但不归属于任何审稿人。
- 跨学科视角的「沟通清晰度」(#4) 最接近写作质量审查，但定义模糊且无输出模板。

**这就是 Discussion 薄弱但无人指出的根本原因**——没有任何审稿人被明确分配「论文结构完整性」的职责。

**改进建议**：
- 方案 A（推荐）：将「论文结构完整性」明确分配给 EIC，在 EIC 的评审维度中增加「结构完整性」子项（包括 Discussion 深度、章节比例、逻辑链密度等），并明确将结构完整性检查清单作为 EIC 的核心工具。
- 方案 B：在 Phase 0.5 中将结构完整性检查的输出强制注入每个审稿人的上下文。

### 问题 2.3：跨学科视角缺少输出格式 [严重程度：🟡 Major]

**现状**：跨学科视角（Peer Reviewer 3）是唯一没有定义输出格式的审稿人。第207-219行列出评审维度后直接是 `---`，没有输出模板。

**改进建议**：
- 补充与其它审稿人一致的输出模板，包括：研究者身份、总体建议与置信度、评分矩阵、关键问题列表、优点。

### 问题 2.4：领域专家缺少评分矩阵 [严重程度：🟠 Minor]

**现状**：方法论专家有详细的评分矩阵（6个维度 × 1-5分），但领域专家没有定量评分，只有定性判断（文献覆盖：充分/部分/不足）。

**改进建议**：为领域专家增加评分矩阵（如：文献覆盖、术语准确性、前沿对接、理论框架、结果解释、领域贡献，各1-5分）。

## 维度三：评审标准是否明确可量化

### 问题 3.1：所有评分均缺乏 Anchor Points [严重程度：🔴 Critical]

**现状**：
- EIC「第一印象」用 1-10 分，但未定义 1、5、10 各代表什么。
- 方法论评分矩阵用 1-5 分，但未定义各分数的含义。
- 原创性/重要性/结构一致性用「高/中/低」，无锚定描述。
- 置信度 1-5 仅有简单描述（1=完全外行, 5=完全内行）。

**具体缺失**：

| 评分项 | 当前状态 | 缺失的 Anchor |
|--------|---------|--------------|
| 第一印象 1-10 | 无锚定 | 3=存在严重缺陷但选题有意义, 5=中等质量需要修改, 7=质量良好仅需小改, 9=可直接接收 |
| 方法论 1-5 | 无锚定 | 1=根本性错误, 3=基本正确但有关键遗漏, 5=严谨无可挑剔 |
| 原创性 高/中/低 | 无锚定 | 高=提出全新理论/方法, 中=对现有方法有显著改进, 低=增量式改进 |
| 置信度 1-5 | 仅1和5有描述 | 2/3/4 无定义 |

**改进建议**：
- 为所有定量评分添加 anchor point 定义。参考 SIGCHI 评审标准的做法：
  ```
  1分 = 存在根本性缺陷，无法通过修改解决
  2分 = 存在严重问题，需要大量修改
  3分 = 基本合格，但有关键改进空间
  4分 = 良好，仅有小问题
  5分 = 优秀，几乎无需修改
  ```
- 为「高/中/低」定性评分添加行为锚定（即：什么具体表现对应「高」）。

### 问题 3.2：严重程度分类缺乏统一定义 [严重程度：🟠 Minor]

**现状**：魔鬼代言人使用 Critical/Major/Minor，Phase 2 编辑决定信也使用类似分类，但缺乏统一定义。

**改进建议**：在 skill 文件开头增加严重程度定义表：
- **Critical**：致命缺陷，可能导致直接拒稿（如：数据造假、核心逻辑错误）
- **Major**：重大问题，必须修改后才能接收（如：方法论缺陷、Discussion 不完整）
- **Minor**：小问题，建议修改但不影响接收决定（如：措辞不当、格式问题）

## 维度四：输出格式是否实用

### 问题 4.1：审稿意见缺少精确位置定位 [严重程度：🟡 Major]

**现状**：所有审稿人的「关键问题」列表只要求「问题描述 + 修改建议」，没有要求标注问题在论文中的具体位置（章节、段落、甚至页码/行号）。

**实际使用影响**：作者拿到评审报告后需要自行定位问题在论文的哪里，效率低下。

**改进建议**：在每个审稿人的关键问题列表中增加必填字段：
```
1. **位置**: [Section X, Paragraph Y / Figure Z / Table W]
   **问题**: [描述]
   **严重程度**: [Critical/Major/Minor]
   **修改建议**: [具体如何改]
   **修改示例**: [给出一个修改后的示范文本片段]
```

### 问题 4.2：跨学科视角无输出模板 [严重程度：🟡 Major]

（同 2.3，此处从实用性角度补充）

**影响**：LLM 执行跨学科视角评审时输出格式不可预测，可能与其他审稿人的报告格式不兼容，导致 Phase 2 综合困难。

### 问题 4.3：修订路线图缺时间线依赖关系 [严重程度：🟠 Minor]

**现状**：Phase 2 编辑决定信的「必须修改项」表格有「预估工作量」列，但修改项之间没有依赖关系标注。

**改进建议**：在修改项表格中增加「依赖项」列，标注哪些修改必须在其他修改之前完成（如：必须先修复方法论缺陷，才能重写 Discussion）。

### 问题 4.4：缺少审稿人之间的交叉引用机制 [严重程度：🟠 Minor]

**现状**：注意事项第3条明确说「各审稿人之间互不交叉引用」，这保证了独立性。但 Phase 2 综合时缺少一个「交叉验证」步骤——哪些问题被多个审稿人独立指出，说明是共识问题。

**改进建议**：Phase 2 增加「共识强度」指标——如果某问题被 3+ 个审稿人独立指出，标记为「强共识」；2个为「共识」；仅1个为「独有问题」。

## 维度五：系统盲区分析——为什么 Discussion 薄弱无人指出

### 根因分析

**盲区形成机制**（因果链）：

```
Skill 设计缺陷 → 无人拥有 Discussion 质量的明确职责 → 结构检查孤立存在 → 
各审稿人按自己框架执行 → 都聚焦技术内容 → Discussion 深度被系统性忽略
```

**5个具体原因**：

1. **职责真空**：结构完整性检查 section 存在于文件中（L315-329），但不归属于任何审稿人。它是「所有人都有责任」的问题，在 LLM 执行中变成了「没有人负责」。

2. **位置劣势**：结构完整性检查放在文件末尾（L315），而各审稿人框架在 L52-253。LLM 处理时很可能先完成所有审稿人评审，然后才读到结构检查要求。

3. **输出模板缺口**：5个审稿人的输出模板中没有一个包含「结构完整性」相关的输出字段。即使 LLM 想要报告 Discussion 问题，也没有规定的地方放。

4. **技术偏见**：5个审稿人的评审维度都是技术导向的（方法论、文献、逻辑、替代解释等），没有维度明确要求「评估论文的写作结构和深度」。

5. **EIC 的「结构一致性」定义过窄**：EIC 的结构一致性检查（L72-76）只关注 title→abstract→intro→conclusion 的纵向逻辑，不涉及各章节的深度和比例。

### 改进建议（系统级修复）

**必须修改**（解决根因）：
1. 将结构完整性检查从文件底部移到 Phase 0 与 Phase 1 之间，作为 Phase 0.5。
2. 明确指定 EIC 负责「论文结构完整性」，在 EIC 评审维度中增加专用的「结构与深度」子维度。
3. 在 EIC 输出模板中增加「结构完整性」section。
4. 在结构完整性检查的输出中生成一个「强制关注项」列表，注入到后续所有审稿人的上下文中。

**建议修改**（增强防护）：
5. 为跨学科视角补充输出模板（同时加入结构审查维度）。
6. 在所有评分标准中添加 anchor points。
7. 在 Phase 2 综合步骤中增加「结构完整性验证」环节。
